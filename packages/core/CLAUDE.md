# packages/core — platform primitives

Moved from the root `CLAUDE.md` (Shared packages). Import per-file subpaths, never the barrel; storage-backed modules are server-only subpaths. The tracker store (`devices`, claims, the per-user index) follows the rules in `apps/web/CLAUDE.md` § "Devices (hardware trackers): the rules" and `docs/features/devices-platform.md`.

## `@paddlesnitch/core` (`packages/core/src`)

Platform primitives:
- `storage` — S3 (prod) / local-fs (dev) object store: `getJson`/`putJson`/`getObject`/`putObject`/`listKeys`/`deleteObject`.
- `auth` — `getAuthUser()` (reads the `tt_id` cookie, verifies the JWT, silent-refreshes via `tt_refresh`).
- `cognito` — Cognito SDK wrapper (signUp, signIn, refresh, revoke, verifyIdToken).
- `url` — URL helpers.
- `types` — platform types (`AuthUser`) **plus the shared boat-class model** (`BoatClass`, `BOAT_CLASSES`, `BOAT_CLASS_INFO`, `Seat`, `CrewMember`, `expectedSeats`, `seatLabel`, `validateCrew`, `isBoatClass`) — re-exported by att's `types.ts` shim and used by the Analyse app for per-paddle boat metadata.

## Buddies (`@paddlesnitch/core/buddies`)

Mutual buddies who see each other's paddles ([`buddies-and-compare.md`](../../docs/features/buddies-and-compare.md)). Request → accept (two people asking each other are buddies), decline (the sender isn't told), cancel, remove (for both); invite links (`/buddies?invite={token}`, NEW LINK retires the old one). **`canViewPaddle(viewer, owner, paddle)` is the one rule**: the owner always; a buddy unless the owner switched sharing off (`users/{id}/buddy-sharing.json`) or set `hiddenFromBuddies` on the paddle; nobody else. Buddies never see notes, AI summaries or emails. tRPC `buddies.*` (requests rate-limited 30/hour, only to real accounts); page `/buddies` (gated in the proxy); ADD AS BUDDY on profiles (`BuddyButton`); BUDDIES with a waiting-requests badge in the account menu. Erasure ends every friendship on both sides; export lists them. **A buddy's paddles:** `/buddies/{userId}` (list) and `/buddies/{userId}/{paddleId}` (read-only `AnalysisView` with `buddy`), via `buddies.paddles` / `buddies.paddle`. Both go through `canViewPaddle` and answer NOT_FOUND for every "no" (stranger, former buddy, sharing off, hidden, nonexistent). They return only safe fields: **a stored paddle summary also carries the note and the AI text, so never hand one to a buddy**; `othersView` (paddles router) is the one projection for anyone but the owner (share links use it too). Owners hide a paddle with Hide from buddies (in the paddle's ⋯ menu) (`paddles.setHiddenFromBuddies`). **Compare with a buddy:** COMPARE WITH ONE OF MINE on a buddy's paddle, and COMPARE WITH… on your own (`paddles.comparable` → `@paddlesnitch/analysis/comparable`: the 100 m squares each route passes through, stored per paddle in `cells.json` beside the summary and built once for older paddles, shortlist by square overlap ≥ 20% or paddled together; then the exact water shared the same way (`sharedSameWayM`: every same-direction pass, so an out-and-back turned at different places counts both legs), ranked by shared km × how alike the distances are; one outing recorded twice is offered once; nothing that shares under 500 m. **Not** nearest start, which is random among club outings that all start within metres) → `/paddles/compare?a={mine}&b={theirs}&bOwner={buddyId}`; B is fetched with `buddies.paddle`, labelled with their name; same-outing and notes are left out. The compare map (`CompareMap`) fits the lines only when they change (`linesKey`), never on a replay tick or scrub, so a zoom holds; from zoom 16 in it draws small arrows along each line showing which way it went (`directionMarks`, `direction-marks.test.ts`). The line comparison itself is `@paddlesnitch/analysis/line-compare` (pure): the longest chain of believable steps matching B to A's line, on moving time; `compareSection` for a stretch picked on the map. **Every pass of a section:** pick two points on a paddle's map → EVERY PASS → `/paddles/section` lists every time you or a buddy paddled between those gates the same way (laps count; another channel doesn't; one outing recorded twice once), fastest first, your best + last few, tick two to compare lines; **SAVE** it with a name (#435) → Paddles → **SECTIONS** (`/paddles/sections`, `/paddles/section?id=`), private to its maker, stored as a two-gate course shape (`gates: [{ line, direction }]` like `CourseMetadata.gates`, timed the same way) in `users/{id}/sections/`, in the export (`sections.passes`/`sections.passLine` → `@paddlesnitch/analysis/section-passes`, `allPasses` in timing/geo; every paddle through `canViewPaddle`; `section-passes.test.ts`). Tests: `buddies.test.ts` (the who-may-see matrix), `trpc-buddies.test.ts`, `buddy-paddles.test.ts` (nothing private leaks), E2E `buddies.spec.ts`.
